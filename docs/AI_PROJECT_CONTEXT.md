# زمینه پروژه برای دستیارهای هوش مصنوعی

> این فایل مرجع اصلی برای ادامه توسعه پروژه است. قبل از هر تغییر مهم، این فایل و README را بخوان.

## معرفی پروژه

این پروژه یک برنامه دسکتاپ Python و PyQt برای فرآیند APQP است. وظیفه اصلی آن دریافت چند فایل Excel مربوط به PFMEA ایستگاه‌های مختلف و ساختن یک فایل Excel نهایی، در همان قالب PFMEA اصلی، است.

کاربر برای هر ایستگاه یک فایل PFMEA جداگانه آماده می‌کند. برنامه باید فایل‌ها را بخواند، ایستگاه‌ها را نشان دهد، کاربر بتواند ایستگاه‌ها را انتخاب یا لغو انتخاب کند و در نهایت ایستگاه‌های انتخاب‌شده را با ترتیب مشخص در فایل خروجی تجمیع کند.

## اولویت‌های قطعی کاربر

این موارد نباید در ارتقاهای بعدی خراب یا حذف شوند:

1. برنامه Python دسکتاپ با رابط PyQt باشد.
2. رابط کاربری فارسی و انگلیسی و دارای تم دارک باشد.
3. فونت اصلی رابط کاربری `Vazirmatn` باشد؛ در صورت نصب نبودن، fallback مناسب استفاده شود.
4. فایل خروجی باید قالب PFMEA اصلی را حفظ کند؛ از جمله:
   - Merge سلول‌ها
   - عرض ستون‌ها و ارتفاع ردیف‌ها
   - Style، رنگ، Border، Alignment و Number Format
   - Header و Footer
   - تنظیمات صفحه و چاپ
   - Conditional Formattingهای Template
5. شیت اصلی خروجی یک شیت PFMEA باشد و ایستگاه‌های انتخاب‌شده به ترتیب کاربر در همان شیت قرار بگیرند.
6. شیت History نباید از چند فایل به شکل ساختگی یا تکراری ساخته شود؛ History باید از Template به‌صورت تمیز و قابل اعتماد منتقل شود.
7. هر فایل ورودی یک ایستگاه PFMEA مستقل است؛ کاربر ممکن است فایل‌ها را به‌صورت مرحله‌ای وارد کند.
8. ستون A کد OPC و ستون B نام ایستگاه است. حالت خرابی‌ها فقط از سلول‌های غیرخالی ستون C در محدوده همان ایستگاه خوانده شوند؛ نباید از ایستگاه یا بخش دیگری جمع‌آوری شوند. همه حالت‌ها باید در جدول زیر هم نمایش داده شوند.
9. ارتفاع ردیف حالت خرابی باید بر اساس تعداد/طول متن‌ها تنظیم شود و کاربر بتواند ارتفاع دستی تعیین کند.
10. ستون USE باید با کلیک روی تمام سطح سلول قابل تغییر باشد، نه فقط روی مربع کوچک Checkbox.
11. با دوبار کلیک روی فایل ورودی در جدول، همان فایل با Excel یا برنامه پیش‌فرض سیستم باز شود.
12. پروفایل محصول باید نام محصول، کد محصول، ترتیب ایستگاه‌ها و وضعیت فعال/غیرفعال بودن هر ایستگاه را ذخیره کند.
13. هنگام Merge نباید فرمول‌های SO و RPN از فایل مبدأ به‌صورت کورکورانه کپی شوند.

## فرمول‌های قطعی PFMEA

در فایل نهایی، برای همه ردیف‌های داده باید این فرمول‌ها صریحاً دوباره نوشته شوند:

- ستون I یعنی SO:
  - `=H[row]*E[row]`
- ستون M یعنی RPN:
  - `=L[row]*H[row]*E[row]`

منظور از `[row]` شماره همان ردیف در فایل خروجی است. این فرمول‌ها باید برای هر ردیف داده در خروجی بازنویسی شوند تا به ردیف‌های قدیمی فایل مبدأ اشاره نکنند.

سلول `AQ2` آستانه درصدی RPNهای بالاتر را نگه می‌دارد. مقدار پیش‌فرض ۲۰٪ است و باید از تنظیمات قابل انتخاب باشد؛ مثلاً ۳۰٪. هنگام Merge:

- فرمول AQ2 باید با درصد انتخاب‌شده به‌روزرسانی شود.
- محدوده RPN در فرمول باید محدوده واقعی داده‌های خروجی باشد.
- Conditional Formatting مربوط به RPN باید از Template منتقل شود و تا ردیف‌های داده خروجی اعمال شود.
- خروجی باید طوری تنظیم شود که Excel فرمول‌ها را هنگام باز شدن دوباره محاسبه کند.

## ساختار فعلی کد

- `pfmea_merger/app.py`: نقطه ورود برنامه؛ اجرای ماژولی و اجرای مستقیم فایل را پشتیبانی می‌کند.
- `pfmea_merger/core/config.py`: تنظیمات Merge و مسیرهای برنامه.
- `pfmea_merger/core/excel_reader.py`: تحلیل Workbook، تشخیص Footer و StationBlockها.
- `pfmea_merger/core/excel_merger.py`: ساخت فایل خروجی، انتقال قالب، Mergeها، History، فرمول‌ها و Conditional Formatting.
- `pfmea_merger/core/profile_manager.py`: ذخیره و بارگذاری پروفایل محصول.
- `pfmea_merger/core/i18n.py`: ترجمه فارسی/انگلیسی.
- `pfmea_merger/ui/main_window.py`: پنجره اصلی و جدول فایل‌ها/ایستگاه‌ها.
- `pfmea_merger/ui/settings_dialog.py`: تنظیمات قابل تغییر.
- `pfmea_merger/ui/style.py`: تم دارک و استایل مدرن رابط.
- `pfmea_merger/tools/e2e_test.py`: تست عملکردی Headless.
- `pfmea_merger/tools/make_sample_inputs.py`: ساخت فایل‌های نمونه از Template.

## تنظیمات و قالب فعلی

- شیت اصلی پیش‌فرض: `PFMEA`
- شیت History ممکن است در فایل با فاصله انتهایی نام‌گذاری شده باشد، مانند `History  `؛ مقایسه نام باید با `strip()` و بدون حساسیت به حروف انجام شود.
- Header پیش‌فرض: ردیف‌های ۱ تا ۸
- شروع داده پیش‌فرض: ردیف ۹
- ستون OPC: A
- ستون نام ایستگاه: B
- ستون حالت خرابی: C
- ستون SO: I
- ستون RPN: M
- سلول درصد RPN: AQ2
- درصد پیش‌فرض AQ2: ۲۰٪

Template مرجع فعلی:

`PFMEA_SBM_SOREN_V0.0  - 14041024.xlsx`

نسخه کپی‌شده برای برنامه:

`pfmea_merger/templates/PFMEA_SBM_SOREN_Template.xlsx`

## رفتار Merge

خروجی باید از Template ساخته شود، نه از Workbook خالی بدون قالب. ترتیب کلی:

1. بارگذاری Template
2. کپی Header
3. کپی ردیف‌های ایستگاه‌های انتخاب‌شده با Mergeها و Styleهای صحیح
4. نوشتن دوباره فرمول‌های SO و RPN برای همه ردیف‌های داده خروجی
5. به‌روزرسانی AQ2
6. انتقال Conditional Formatting و Differential Styleها
7. کپی Footer از Template
8. کپی تمیز History از Template
9. ذخیره خروجی و درخواست Recalculate از Excel

در انتقال Style نباید `_style` یک سلول از Workbook مبدأ مستقیماً به Workbook خروجی اختصاص داده شود؛ شناسه‌های Style بین Workbookها متفاوت‌اند و این کار می‌تواند خطای `IndexError: list index out of range` ایجاد کند. Styleها باید با کپی اجزای عمومی مانند Font، Fill، Border، Alignment، Number Format و Protection منتقل شوند.

## تست و کنترل کیفیت

بعد از هر تغییر مهم این موارد بررسی شوند:

```powershell
python -m compileall -q pfmea_merger
python -m pfmea_merger.tools.e2e_test
```

تست عملکردی مورد انتظار:

```text
RESULT: 36 passed, 0 failed
```

حداقل این موارد باید بررسی شوند:

- Merge همه فایل‌های نمونه
- Merge بخشی از فایل‌ها
- ترتیب و وضعیت Checkboxها
- ذخیره و بارگذاری Profile
- درست بودن History
- یکسان بودن Mergeهای مهم با Template
- حفظ عرض ستون‌ها
- وجود Conditional Formatting
- مقدار و فرمول AQ2
- درست بودن فرمول I و M در ردیف‌های جابه‌جا شده
- شناسایی درست Footer و نادیده گرفتن ردیف‌های اضافی انتهای فایل

## محدودیت‌های محیط توسعه

- برنامه برای Windows و اجرای واقعی با PyQt طراحی شده است.
- در بعضی محیط‌های Sandbox کتابخانه‌های سیستم Qt مانند `libGL`، `libEGL` و `libxkbcommon` وجود ندارند؛ در این حالت GUI قابل اجرای واقعی نیست و باید Syntax و Backend با تست Headless بررسی شوند.
- GPU برای پردازش مستقیم فایل Excel توسط openpyxl کاربرد عملی ندارد. Merge، XML و Styleهای Excel عمدتاً CPU/IO هستند. نباید برای استفاده اجباری از GPU ساختار برنامه یا صحت فایل خروجی قربانی شود.

## قوانین توسعه

- کلیات برنامه و جریان کاری اصلی تغییر نکند مگر با درخواست صریح کاربر.
- قبل از تغییر ساختار Excel، Template و فایل‌های Sample بررسی شوند.
- برای هر اصلاح، تست چندحالته اجرا شود.
- پیام‌ها و خطاها برای کاربر فارسی و قابل فهم باشند و در حالت انگلیسی ترجمه داشته باشند.
- از اضافه کردن داده‌های حدسی، حالت خرابی از فایل دیگر یا History ساختگی خودداری شود.
- هنگام اعلام اتمام کار، فایل‌ها، تست‌ها و محدودیت‌های واقعی به‌صورت شفاف گزارش شوند.
